# 校园小助手 Campus Agent

面向学校学生的 Web 版智能助手 Agent，支持 **工具调用、长期记忆、RAG 知识库检索、自主学习升级**。

## 高德地点与评分（2026-10-27）

已接入高德 Web 服务 POI 2.0 接口、聊天工具和配置入口。当前配置的 Web 服务 Key 已通过真实连接测试，并确认黑龙江八一农垦大学的高德学校中心点；密钥不写入聊天记录、工具事件或公开接口响应。

1. 按[高德官方申请指南](https://developer.amap.com/api/webservice/create-project-and-key)创建应用、添加 Key，平台选择“Web 服务”，并核对地点搜索服务权限。
2. 刷新页面后发送“配置高德”，在聊天卡片的高德密码框填写 Key，点击“保存高德配置”或“测试高德连接”。高德密钥与 DeepSeek 分开保存，空白输入保留原 Key；配置接口只返回掩码，不发送到聊天或工具记录，HTTP 客户端日志中的 Key 查询参数也会遮盖。
3. 默认按“大庆市 / 黑龙江八一农垦大学”搜索学校；坐标留空时精确匹配校名，存在同名地点时提示填写核对后的高德坐标。周边默认3000米，可在卡片中调整。
4. 可问“一食堂在哪”“校内图书馆在哪”“学校附近评分高的餐馆”“学校附近3公里内的咖啡店”。地点卡片展示实际返回的地址、评分、人均、电话、营业时间和来源链接；可以更新详情、打开地图或从学校导航。校内查询同时检索现有资料，地图没有收录时不编造坐标。

[POI官方接口](https://developer.amap.com/api/webservice/guide/api-advanced/newpoisearch)仅对部分餐饮、酒店、景点、影院地点提供评分和人均消费，不提供用户评论正文；缺失字段显示“未提供”，不生成口碑摘要或假评论。按评分排序仅对本次最多25个候选排序，不代表全城排名。地图时间不是实时营业确认，距离为学校中心到地点的直线距离；“校外”暂按学校周边检索，缺少校园边界依据时不保证所有结果都在校外。

实现：backend/maps.py；工具search_campus_places / get_campus_place_detail；接口GET/POST /api/maps/config、POST /api/maps/test、POST /api/maps/search。结果卡片随工具事件保存，刷新可恢复，模型能读取上次地点快照理解追问。仍然只有对话界面，无独立地图页面。

验证：Python81项（79通过、2个既有可选PDF依赖用例跳过），Node7项，Chromium浏览器2项；真实高德测试返回3条附近餐馆结果，其中3条带评分。浏览器测试不写真实配置，测试对话已清理。

## 黑龙江高校通用模板（2026-10-27）

当前项目已从单校配置抽象为可切换的学校模板。内置黑龙江省普通高校目录（当前目录80所，学校数量按官方名单变化），并支持在聊天里的“设置 → 学校模板”加入未收录学校；因此可以扩展到用户所说的82所及后续新增学校。

- 每所学校有独立的学校 ID、城市、官网字段、地图学校名称、坐标和周边半径；切换学校时保留 DeepSeek 与高德密钥。设置卡片可直接保存当前学校官网，当前八一农垦大学已配置 `https://www.byau.edu.cn/`。
- 知识库文档、知识块和对话按当前学校隔离；原有黑龙江八一农垦大学资料继续归属 `hlby`，切换到其他学校不会把这些校规或食堂资料带过去。
- 官网资料需要按学校分别抓取和导入，不能把一所学校的规章、电话或菜单当成另一所学校的事实。当前学校选择和新学校添加都在聊天设置卡片中完成，没有新增独立功能页面。

接口：`GET /api/schools`、`POST /api/schools/select`、`POST /api/schools`、`PATCH /api/schools/{school_id}`；实现集中在 `backend/campus_profiles.py`，知识库隔离由 `backend/db.py` 与 `backend/rag.py` 完成。

## 校园问答与办事导航（个人使用第一阶段）

发送“办事导航”，聊天中展示 9 类事项和官网电话簿查询；已解析 277 条联系人，支持按部门、学院或岗位查询。每项展示相关原文、咨询方式和资料缺口，缺少办理细则时不生成假流程。对话回答附检索参考资料，保存后仍可查看官网或已收录原文；入库时间不等于发布时间。

检索已增加标题权重、校园别称和适用范围限制；旧的无原文链接整理版电话簿仅供人工核对，不参与自动问答。详见 `docs/第一阶段-校园问答与办事导航.md`。个人课表、成绩等功能仍待真实教务接入。

## 快速开始

1. **申请 API Key**：到 [platform.deepseek.com](https://platform.deepseek.com) 注册，在「API Keys」页创建 Key。
2. **启动**：双击项目根目录的 `启动.bat`（首次会自动安装依赖），浏览器自动打开 `http://127.0.0.1:8300`。
3. **配置**：发送“修改设置”，在聊天卡片的密码框粘贴 API Key →“保存配置”或“测试连接”。密钥不作为聊天消息发送。
4. **选择学校**：在同一张设置卡片的“学校模板”中选择当前学校；需要时填写学校官网和地图坐标，再导入该校资料。
5. **开始使用**：直接提问即可，所有功能均在对话中完成。
   - 发“查看知识库”“查看记忆”，在聊天卡片内检索、补充或删除内容。
   - 发“学习这段对话”，在卡片中提炼；发“审核学习内容”采纳或拒绝知识。
   - 自动学习策略也在“修改设置”的卡片内调整。仅打开操作卡片不会触发自动提炼。

> 手动启动方式：项目根目录执行 `pip install -r requirements.txt`，然后 `cd backend` 并执行 `python main.py`。

## 技术架构

```
前端 frontend/index.html（单一对话界面，按需嵌入操作卡片）
        │  HTTP / SSE 流式事件
后端 FastAPI（backend/）
 ├─ agent.py    ReAct 循环：组装上下文 → LLM → 工具调用 → 观察 → 回答
 ├─ tools.py    工具层（OpenAI function calling 协议，可插拔）
 ├─ rag.py      RAG：切块 + TF-IDF 余弦相似度检索（纯本地离线）
 ├─ campus_profiles.py 学校目录与学校级配置切换
 ├─ memory.py   长记忆：保存/检索/对话后自动提炼
 ├─ learning.py 学习引擎：知识提炼 → 审核 → 采纳入库；反馈统计
 ├─ db.py       SQLite 存储（对话/消息/记忆/知识/学习/反馈）
 └─ llm.py      DeepSeek 客户端（OpenAI 兼容协议）
```

- **大模型**：DeepSeek（默认 `deepseek-flash`，可切换 `deepseek-v4-pro`），均使用普通对话模式以兼容工具连续调用；回答以 SSE 流式逐字推送，调用失败自动重试。模型和调用参数参考 [DeepSeek 官方文档](https://api-docs.deepseek.com/)。发送“修改设置”，在密码框填写自己的 API Key，点击「测试连接」会先保存当前设置，再验证连接。
- **存储**：全部本地化 —— 数据在 `backend/campus_agent.db`，配置在 `backend/config.json`；知识库和对话带学校 ID，删除即重置。

## 部署与安全提示

- 当前为单用户本机演示模式，服务仅绑定 `127.0.0.1`。
- 若部署到服务器供多人使用，请务必：修改 `host` 为 `0.0.0.0` 前增加反向代理与鉴权（如 Nginx + 登录）、启用 HTTPS、并为不同学生做用户隔离（当前对话/记忆全局共享，多人使用会互相可见）。
- `config.json` 中的 API Key 为明文存储，注意文件权限；不要将该文件提交到代码仓库。

### 更新官网知识

在项目根目录执行：

```powershell
python -X utf8 -u -B output/byau_crawler.py --max-pages 800
# 如需补抓章程、校历和短通知中的 PDF，先安装可选依赖：
python -m pip install -r output/requirements-crawler.txt
python -X utf8 -u -B output/byau_pdf_enrich.py
python -X utf8 -B output/byau_import_rag.py stats
python -X utf8 -B output/byau_import_rag.py import
```

爬虫只访问 `https://www.byau.edu.cn/` 主站公开 HTML 页面，优先重新抓取已入库资料，再发现新链接；正文来自实际内容容器，保留段落、表格与附件链接，不使用 SEO 摘要代替全文。每次请求间隔至少 0.5 秒，最多同时使用 3 个连接。抓取缓存、发布时间、抓取时间和统计保存在原项目 `output/byau_crawl_state.json`、`output/byau_crawl_report.json`。可选的 PDF 补抓脚本解析章程、校历及短通知中嵌入的本站 PDF，记录原地址并提取全部页面文字，结果保存在 `output/byau_pdf_report.json`；扫描件会标记为待 OCR，不冒充已识别正文。图片和 Word 附件尚不自动解析。

导入只接纳新版本确认的完整正文，按来源地址更新对应文档与切块，保留原文档编号和其他资料。导入前建议使用 SQLite backup 备份数据库。主程序使用内存检索索引，批量导入后重启 Web 服务使更新生效。单次页数上限不代表全站覆盖全部完成。

## 常见问题

- **端口冲突**：修改 `backend/config.json` 中的 `port`。

## 随机吃饭推荐（2026-10-27）

输入“中午吃什么”“推荐一下吃什么”“午饭推荐几个”等，会直接从食堂知识库随机选3—5道菜，显示菜名、原始价格、食堂/楼层/档口和资料来源。同轮菜名不重复，优先分散档口；说“换一批”会在候选充足时避开上一轮菜名，并沿用上一轮食堂、楼层和数字预算条件。候选不足时如实列出已有数量，不编造补足。

推荐由本地菜单抽样完成，无需调用模型；普通查询沿用原有问答。菜单中的加量/大份等表头和单位保留，饮料、加料和早餐栏目不作为正餐候选；未核实实时营业情况。涉及过敏、忌口等需求保留在通常问答路径，不将随机抽样作为饮食适用性判断。

实现：`backend/dining.py`、Agent聊天分流和`recommend_campus_food`工具；测试：`tests/test_dining.py`；在线验证报告：`output/dining_recommendation_report.json`。原知识库和源文件不作修改。
